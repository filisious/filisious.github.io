# Alireza Khorasani — цифровая визитка

Готовый статический проект. Никакой сборки, npm, сервера приложений, платных API или внешних запросов страницы. Единственная библиотека — локальная qrcode-generator 1.4.4 (MIT).

## Файлы

- index.html — структура, исходные метаданные и запасные контактные ссылки.
- config.js — контактные данные, переводы, необязательный SITE_URL.
- styles.css — дизайн, размеры, системная тема, RTL, reduced motion.
- script.js — языки, vCard, копирование, sharing, QR.
- vendor/qrcode.js и vendor/LICENSE — локальный генератор QR и лицензия.
- contact.vcf — запасной контакт для отключённого JavaScript.
- favicon.svg — монограмма AK.
- icons/icon-192.png и icons/icon-512.png — иконки домашнего экрана.
- manifest.webmanifest — метаданные установки.
- sw.js — offline-кэш после первого успешного открытия.
- README-RU.md — эта инструкция.
- QA.md — результаты проверок и ограничения.

## Публикация: по шагам

Лучше выполнять первичную загрузку с компьютера.

1. **Аккаунт.** Откройте https://github.com/signup . Укажите email, пароль и свободное имя пользователя; подтвердите email и выберите бесплатный план. Результат: вы вошли в GitHub и видите свой профиль. Имя пользователя станет частью адреса визитки.

2. **Репозиторий.** Откройте https://github.com/new . В поле Repository name введите `business-card`. Выберите **Public**. Добавьте README через соответствующую галочку и нажмите **Create repository**. Результат: открыта страница вашего репозитория. Для адреса без дополнительной папки вместо `business-card` назовите репозиторий точно `USERNAME.github.io`, подставив своё имя пользователя.

3. **Загрузка.** Распакуйте архив. В репозитории выберите **Add file → Upload files**. Перетащите всё содержимое папки `business-card`, включая папки `icons` и `vendor`. Не загружайте сам ZIP и не создавайте лишний уровень папки `business-card`. Нажмите **Commit changes**. Результат: `index.html`, `config.js`, `styles.css` и остальные файлы видны сразу в корне репозитория; `icons` и `vendor` видны как папки.

4. **GitHub Pages.** Откройте **Settings → Pages**. В разделе **Build and deployment** выберите **Source: Deploy from a branch**. Для **Branch** выберите `main`, рядом — `/(root)`, затем **Save**. Результат: GitHub запускает публикацию. В **Actions** процесс должен завершиться зелёной отметкой; это может занять несколько минут. При ошибке сначала проверьте наличие `index.html` в корне и публичность репозитория.

5. **Адрес.** Вернитесь в **Settings → Pages**. После публикации появится сообщение **Your site is live at** и **Visit site**. Откройте указанный HTTPS-адрес. Он будет иметь вид `https://USERNAME.github.io/business-card/` или `https://USERNAME.github.io/`. Здесь USERNAME — пример, а не существующий адрес вашего сайта. Результат: открывается визитка с рабочими стилями и контактами.

6. **SITE_URL.** По умолчанию оставьте `SITE_URL: ''` в `config.js`: QR и Share используют текущий публичный адрес без параметров и якоря; окончание `index.html` удаляется. Ничего менять после публикации не требуется. Если хотите, чтобы QR всегда вёл на один конкретный адрес даже при просмотре копии сайта, укажите полный опубликованный HTTPS-адрес в SITE_URL. Localhost и открытие через `file:` не генерируют QR без заданного публичного SITE_URL. Результат: QR ведёт на опубликованную визитку, а не на адрес компьютера разработчика.

7. **QR.** Откройте опубликованную страницу на телефоне, нажмите «Показать QR». Поднимите яркость экрана, если есть блики. Другим телефоном откройте обычную камеру, наведите её на весь квадрат вместе с белыми полями и нажмите найденную ссылку. Результат: другой телефон открывает ту же визитку. Повторите на расстоянии примерно 20–50 см. QR чёрный на белом в обеих темах, с quiet zone 4 модуля и коррекцией ошибок M. Не обрезайте белые поля на скриншотах. Длинный SITE_URL увеличивает плотность QR, поэтому предпочтителен короткий GitHub Pages URL.

8. **Save Contact.** На iPhone откройте страницу в Safari и нажмите «Сохранить контакт». Если появляется предпросмотр контакта, выберите создание/сохранение контакта; если загрузился файл, откройте его через загрузки Safari или «Файлы» и сохраните. На Android откройте страницу в Chrome; нажмите кнопку, откройте загруженный `Alireza-Khorasani.vcf` и выберите приложение «Контакты» и нужный аккаунт. Если система не предлагает импорт автоматически: Google Contacts → раздел управления контактами/организации → импорт из файла → выберите VCF. Названия пунктов зависят от версии системы. Результат: имя Alireza Khorasani, телефон и email сохранены; компания не добавлена. Telegram и WhatsApp также записаны как URL и в NOTE: отдельные приложения могут показывать только один URL. Перед повторным тестом удалите тестовый контакт, чтобы не создавать дубликаты.

9. **Домашний экран.** iPhone: Safari → меню «Поделиться» → «На экран Домой» → «Добавить». Android: Chrome → меню ⋮ → «Добавить на главный экран» / «Установить приложение» → подтвердить. Результат: появляется значок AK. После первого полного онлайн-открытия и успешного кэширования интерфейс доступен без сети; отправка сообщений, звонки через приложения и первое открытие ссылки другим человеком требуют соответствующего соединения. Не рассчитывайте на вечное хранение кэша: ОС может удалить его.

10. **Изменения.** В GitHub откройте `config.js` → карандаш **Edit this file**. Измените `phone` в международном формате, `phoneDisplay`, `email` или `telegram` без @; описания находятся в `translations.en/ru/fa.description`. Не удаляйте кавычки и запятые. Нажмите **Commit changes**. При необходимости поправьте исходные метаданные и запасные ссылки в `index.html`, а также запасной `contact.vcf`: они нужны без JavaScript и для поисковых роботов. При изменении имени обновите manifest. В `sw.js` увеличьте `VERSION`, например `PREFIX+'v1'` → `PREFIX+'v2'`. Результат: GitHub публикует обновление, после открытия онлайн страница получает новые данные. Если старые данные ещё видны, обновите страницу повторно; проверьте также в приватной вкладке. Главный рабочий интерфейс и скачиваемый VCF автоматически используют config.js.

## Работа и приватность

Язык браузера выбирается при первом открытии: RU для русского, FA для персидского, EN для остальных. Ручной выбор хранится только в localStorage. Cookies и аналитики нет. Запрет localStorage не мешает работе переключателя в текущей вкладке. GitHub как хостинг и внешние мессенджеры применяют собственные правила обработки данных.

Тема автоматически следует настройкам устройства. QR-режим закрывается кнопкой или Escape, удерживает фокус внутри диалога и блокирует прокрутку фона. Если Web Share API отсутствует или возвращает ошибку, копируется URL. Если запрещены оба механизма копирования, появляется поле для ручного выделения. Отмена системного sharing не показывается как ошибка.

## Технические решения

Системные шрифты: Apple/Segoe UI/Arial; Persian — Tahoma/Segoe UI/Arial. Точный вид зависит от установленных шрифтов устройства. Макет использует логические направления и RTL, но URL, телефон и монограмма остаются LTR. Основная область 480 px, отступы 20–28 px на мобильных, кнопки 44–56 px, радиус 8 px.

VCF: vCard 3.0, CRLF, UTF-8, перенос строк до 75 байт с продолжением, стандартные N/FN/TEL/EMAIL/URL/NOTE. Основной файл генерируется локально из config.js. Успешная загрузка не означает автоматически, что человек подтвердил импорт в контакты.

Service worker использует network-first с ограничением ожидания 3,5 секунды и fallback на кэш. При первом посещении offline-копии ещё нет. PWA не запрашивает уведомления и не выполняет фоновые API-запросы. Весь код открыт и редактируется обычным текстовым редактором. Для локального запуска при установленном Python: откройте терминал внутри папки и выполните `python -m http.server 8000`, затем откройте http://localhost:8000/ . Результат: локальный интерфейс; production QR появится после публикации либо задания SITE_URL. Остановка: Ctrl+C.
